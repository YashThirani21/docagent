# Reference run: geo-l4-fix4 (model outputs, NOT verified labels)

These are the drawing extractor's own outputs on all 11 drawings, from the version I decided to freeze. Every new extractor version gets compared against them. They're not perfect, they're just the best full run I had.

## How this version came about

**Reading whole sheets didn't work.** 10 of the 11 drawings draw their dimensions and GD&T as vector shapes, not text, so the values have to be read from the picture. One VLM call on a full page missed or made up about half of them.

**Tiles were better, but messy.** My first version split each sheet into overlapping tiles and had the VLM transcribe each one. Recall was high, but about half the entries were junk: duplicates from the overlaps, frames split into single letters, a value copied from a prompt example. GD&T symbols were 0% correct. The model was finding, placing and reading values all in one go on overlapping crops, and no amount of cleanup afterwards could fix that.

**So I split finding from reading.** The annotations are drawn in blue, so grouping the blue vector paths finds them geometrically: roughly one box per annotation (19 boxes on CTC-01, where the tile version had produced 32 junk-filled entries). Then the VLM reads each callout once, in a short call. Datum letters come from OCR, "belongs to" from a crop at the end of the leader line, and confidence from how many checks pass. PDFs and pictures each have their own way of finding annotations, then share the same reading step.

**Then four rounds of fixes on Colab (L4 GPU).** Each one was diagnosed from the output files and the cached model replies:
- **Fix 1:** stopped repetition loops (one read had repeated a value 15 times), lowered the token limit, rebuilt frame rows from single letters, read the title block and notes from the image. Precision 0.47 → 0.88, but 4 datum letters got glued onto neighbouring rows.
- **Fix 2:** only a run of letters joins a frame row, a lone letter stays a datum. Datums 0.86, nothing got worse.
- **Fix 3:** word annotations like "4 COPLANAR SURFACES" get rebuilt from the text layer instead of being dropped as notes. Recall 0.81 → 0.87, but two datums were lost on PDFs and one picture-route rule hurt pictures (precision 0.81 → 0.59).
- **Fix 4:** reverted that picture rule, kept phrase order, and stopped frame rows with datums from grabbing an extra letter. The lost datums came back and nothing new was missed. **This is the version in this folder.**

## How to read a comparison against it

The drawing eval reports two numbers. **Agreement** says how much a new version changed compared with fix4. It doesn't say whether the change is right. Fix4 has mistakes, so a version that fixes one shows *lower* agreement. That's why `python -m eval drawing` always reports accuracy on the labelled sheets next to it. Those labels (`eval/datasets/drawings/*.json`) are separate files drafted by the AI assistant, not taken from fix4 or any other extractor output.
